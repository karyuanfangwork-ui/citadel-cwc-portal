## Implementation Plan

### Phase 0 — Stop-the-bleed hotfix (½ day, single PR, no schema change)
1. **C2 fail-closed SoD** — change `catch` blocks in `sod.middleware.ts:70,111` to return `503 { error: 'SoD check unavailable' }`; replace `console.warn` (M16) with `logger.error({ applicationId, userId, attemptedAction })`.
2. **M14** — delete hardcoded fallback key; throw on boot if `CREDIT_ENCRYPTION_KEY` missing (add to `config/index.ts` validation).
3. **H10** — guard `req.user` in `reviewStatement` and other controllers using `!`; introduce small `requireUser(req)` helper.
4. **H7** — pick one of `financial.routes.ts` / `financials.routes.ts` as canonical, delete the other, redirect mounts in `credit.routes.ts`. Same audit for the `scorecard*` / `score*` route quartet.

### Phase 1 — Authorization & tenancy (1–2 days)
5. **C3** — add `assertBorrowerAccess(req.user, borrowerProfileId)` middleware; mount on all `:borrowerProfileId/*` routes (director, shareholder, UBO, financial, document, related-party).
6. **L25 + H5** — create `validators/approval.validator.ts` with zod schemas for `createMatrix`, `submitApproval`; add enum validation for `statementType`/`period` (M19).
7. **M15** — in `clamav.controller.ts` validate `document.filePath.startsWith(config.uploadDir)` and reject `..` segments.

### Phase 2 — Data integrity & audit chain (2–3 days)
8. **C1** — migration: add `nricPassportEncrypted`, backfill via script, drop plaintext column; route reads through `PiiReadLogService.logRead()`. Apply same pattern to any `idNumber`/`passportNumber` on shareholder/UBO models.
9. **C4 + M13** — wrap `reviewStatement`, `submitApproval`, `recordCommitteeVote` in `prisma.$transaction(async tx => { … })`; re-fetch and recount approvals inside the txn; emit `auditChain.appendEvent(tx, …)`.
10. **M12** — emit `DOCUMENT_DELETED` / `DOCUMENT_VERSIONED` audit events from `creditDocument.service`.
11. **H9** — in `scoring.service.executeScore`, add `effectiveFrom <= now AND (effectiveTo IS NULL OR effectiveTo >= now)` to active-scorecard query; reject with 409 if no version active.

### Phase 3 — Performance & schema hygiene (1 day)
12. **M18, L23** — Prisma migration:
    - `@@index([deletedAt])` on `CreditDocument`
    - `@@index([applicationId, eventType, createdAt])` on `CreditAuditEvent`
13. **H8** — paginate/filter `decisions` include in application fetch; add dedicated `getApprovalSummary(applicationId)` count query.
14. **M17** — replace deep `approvedBy` include in `getScorecard` with `select: { id, name }` projection.
15. **L24** — refactor covenant monitor job to single grouped query (`groupBy({ by: ['covenantId'], _max: { testedAt } })`) then bulk-fetch test rows; chunk for >5k covenants.

### Phase 4 — Hardening, hygiene, ops (1 day)
16. **H6, L21** — strict-type pass on `approvalMatrix.service.ts`, remove tautologies; coerce blank PII strings to `null` at service boundary.
17. **L20** — migrate export-token store to Redis (`exportControl.service.ts`) with TTL; document KMS path for Phase 5.
18. **M11, L22** — extend `creditSmokeTest.ts` with: (a) SoD-violation rejection, (b) scoring against expired scorecard rejected, (c) NRIC stored encrypted + PII read log row written, (d) export-token lifecycle, (e) covenant monitor produces breach event. Assert response status + shape on every step.

### Phase 5 — Followups (track as tickets)
- KMS-backed key rotation for `CreditEncryptionService`.
- Move approval-matrix version pinning to a `matrixVersionId` FK on `CreditApplication` so mid-flight matrix edits cannot retroactively change required approvers.
- Replace in-process job loop with the existing BullMQ queue infra for `monitor.job.ts`.
