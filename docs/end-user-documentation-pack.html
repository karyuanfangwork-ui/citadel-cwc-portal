User Quick Start Guide

Purpose
Get a new user productive in under 10 minutes.
Scope
Login, navigation, first request, tracking.
Audience
All employees (especially new joiners).

Step 1 — Log in

  1. Open the CWC portal in your browser. The Login screen appears.
  2. Enter your company email and password, then select Sign In.
  3. Forgot your password? Select Forgot password to reach the Forgot Password screen and follow the email link.

Step 2 — Get your bearings (the Dashboard)

After login you land on the Dashboard — your home base. From here you can see a summary of your requests, recent company announcements, and quick links to the three service desks.

WhereScreenUse it to…
Home/ DashboardSee request summary cards and announcements.
My Requests/my-requestsView, search and filter everything you've raised.
Agent Dashboard/agent(Agents/Admin) Pick up and progress tickets.
Approvals/approvals(Managers) Approve or reject items waiting on you.
IT Assets/assetsView and manage assigned IT equipment.
Announcements/announcementsCompany-wide notices and updates.
Notifications/inboxReal-time notifications (also pushed via SSE).
Knowledge Base/kbFind self-help articles before raising a ticket.
Reports/reportsView service desk performance and metrics.

Step 3 — Raise your first request

  1. From the Dashboard, choose the desk you need: IT Support, HR Services or Group Finance.
  2. Pick the category that matches your need (e.g. Get IT Help).
  3. The Create Request wizard opens: Select Type → Fill Details → Review & Submit.
  4. Complete the required fields, attach any files, and select Submit.
  5. You'll get a confirmation and a request ID — your ticket is now Submitted.

Step 4 — Track it

Open My Requests and select your ticket to reach the Request Detail page. The Workflow Stepper at the top shows exactly where your request is and what happens next. Add comments, upload files, and respond when a request is marked Action Required.

Best Practices
  • Search the Knowledge Base first — many issues have an instant answer.
  • Pick the most specific category; it routes your ticket to the right team faster.
  • Write a clear, one-line summary and attach screenshots where relevant.
Common Mistakes
  • Raising an IT ticket under HR (or vice-versa) — this delays routing.
  • Leaving required fields vague (“not working”) instead of describing the symptom.
  • Closing the browser before pressing Submit on the final wizard step.
Troubleshooting
  • Can't log in? Use Forgot password; if it persists, raise a Get IT Help ticket via a colleague or call the IT desk.
  • Don't see a desk or category? Some categories are role-restricted (e.g. hiring). See Document 9.
Example Scenario Priya's laptop won't connect to Wi-Fi. She opens IT Support → Get IT Help, describes the symptom, attaches a screenshot of the error, and submits. Her ticket is Submitted, then In Review within the 24-hour SLA, and she's notified at each step.

End User Standard Operating Procedure (SOP)

Purpose
Define the official procedure for raising and managing a request end-to-end.
Scope
All three desks; creation through closure.
Audience
All employees, managers, approvers.

2.1 The Standard Request Lifecycle

Submit→ In Review→ Approval
(if required)→ In Progress→ Action
Required?→ Resolved / Completed

2.2 Procedure

  1. Identify the need and the right desk. Check the Service Catalog to choose the correct request type.
  2. Self-serve first. Search the Knowledge Base. Raise a ticket only if no article resolves it.
  3. Create the request via the Create Request wizard. Complete all required fields and attach supporting documents.
  4. Submit and record the ID. The system assigns a tracking ID and sets status to Submitted. You and the assigned team are notified.
  5. Respond promptly to “Action Required”. If the agent needs more information, the ticket moves to Action Required and the SLA may pause until you reply.
  6. Approvals (where applicable). Procurement, hiring and finance items route to approvers automatically. The SLA timer pauses while awaiting approval (see Business Rules).
  7. Confirm resolution. When the agent marks the ticket Resolved / Completed, review the outcome. Re-open by commenting if the issue persists.

2.3 User Responsibilities

  • Provide accurate, complete information and valid business justification.
  • Respond to Action Required requests within the stated window.
  • Use the correct desk and category; do not raise duplicate tickets.
  • Keep confidential information appropriate to the request.

2.4 Department Responsibilities

Ticket Lifecycle Guide

Purpose
Explain every ticket status and how requests progress.
Scope
10 workflow tracks; the Request Detail & Workflow Stepper screens.
Audience
All employees and approvers.

CWC uses different status tracks depending on the request type. Most simple tickets follow the General track below. Software and hardware procurement each have their own track. Hiring, onboarding, offboarding, finance and chargeback requests follow their own specialised tracks. The Workflow Stepper on the Request Detail page always shows your ticket's position in plain language.

4.3 New Hiring Request

The HR Hiring track (request type New Hiring Request) is the longest workflow in CWC. It runs from a hiring manager's request, through a two-tier executive approval (CEO then Group Deputy CEO), into recruitment (job posting, candidate review, interview, screening) and finally the Letter of Acceptance (LOA) cycle. On completion it can automatically spin up an Onboarding ticket (Section 4.4). The request can only be raised by a user with the Hiring Manager role, and the HR agent drives most of the recruitment steps while the hiring manager makes the candidate and LOA decisions.

Submitted→ CEO Approval→ Group DCEO Approval→ Job Posted→ Manager Review→ Interview Scheduled→ Interview Feedback→ HR Screening→ LOA Pending→ LOA Approved→ LOA Issued→ LOA Accepted→ Completed

Best Practices
  • Provide a detailed budget breakdown — lump-sum proposals without line items get queried back by Finance.
  • Align the budget period with the company's financial calendar (Q1–Q4 or annual).
  • The SLA timer pauses during CFO approval.
  • CFO rejection loops back to Submitted — you can revise and resubmit without creating a new request.

  • There is no payment phase — this is a budget adoption, not a purchase. After CFO approval, Finance updates the record and closes the ticket.
How it works under the hood

Budget Proposal uses a different, simpler workflow than Purchase Requisition (no Group DCEO, no payment phase). The actions are keyed off an isBudgetProposal flag (request type code BUDGET_PROPOSAL) in workflowActions.ts:

  1. Acknowledge — FIN_ACKNOWLEDGE is shown to Finance desk agents/admins at SUBMITTED or FINANCE_PENDING_ACK → POST /finance-workflow/requests/:id/acknowledge.
  2. Route to CFO — ROUTE_TO_CFO_BP at FINANCE_ACKNOWLEDGED (no finalised amount/invoice) → POST /finance-workflow/requests/:id/route-to-cfo; reassigns to the CFO and pauses the SLA.
  3. CFO decision — CFO_DECISION_FIN at PENDING_CFO_APPROVAL_FIN → POST /finance-workflow/requests/:id/cfo-decision. On approval the backend routes Budget Proposals to FINANCE_IN_PROGRESS (not PAYMENT_PROCESSING_FIN).
  4. Update & close — CLOSE_BUDGET_PROPOSAL at FINANCE_IN_PROGRESS → POST /finance-workflow/requests/:id/update-and-close-budget → TICKET_CLOSED_FIN.

Purpose
Document the rules that govern SLAs, escalation and approvals.
Scope

All employees, managers, approvers.

8.1 SLA Definitions

Each request type has a Service Level Agreement (SLA) measured in hours from submission. The deadline is shown on the request.

SLAApplies to
24 hoursGet IT Help, Email Management, Report System Problem, Question for HR
48 hoursSoftware Installation, New Hiring, Onboarding, Offboarding
72 hoursNew Hardware, Purchase Requisition, Inter-Company Chargeback, Budget Proposal

8.2 SLA Pause & Resume

  • The SLA timer pauses automatically when a request enters an approval stage (e.g. awaiting CEO/CFO/Group DCEO/manager) or when the agent sets the status to Action Required (waiting on the requester's response).
  • It resumes when the approval is decided or the requester responds, and the original time remaining is preserved (the deadline shifts by the paused duration).
  • A request that stays paused longer than 14 days is auto-resumed to prevent it stalling indefinitely.

8.3 Escalation Procedures

If a request breaches its SLA deadline, the system records a breach and notifies the assigned agent and administrators. Multi-tier escalation rules can be configured per request type by administrators — for example, notifying senior management when an SLA breach goes unresolved for a specified number of hours.

SLA Breached→ Escalation Tier 1
(Agent / Admin)→ Escalation Tier 2
(CEO / Senior Mgmt)→ Critical Alert

Illustrative chain — actual trigger hours, escalation tiers and target roles are configured per request type by administrators via Admin Settings. Eligible escalation roles include Admin, Agent, HR, IT, Finance, CEO, CTO, CFO and Group DCEO. The default configuration triggers a breach notification to the Admin role; additional tiers can be added as needed.
