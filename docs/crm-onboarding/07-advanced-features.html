Email & Calendar Integration

The CRM supports Google Workspace and Microsoft Outlook integration via OAuth 2.0. Once connected, emails and calendar events are synced automatically, and activities are logged to the corresponding CRM records without manual entry.
OAuth Connection & Sync Flow
sequenceDiagram participant U as User participant CRM as CRM participant O as OAuth Provider participant S as Sync Engine U->>CRM: Click "Connect Google/Outlook" CRM->>O: Redirect to OAuth consent O->>CRM: Return authorisation code CRM->>CRM: Store refresh token (encrypted) CRM->>S: Activate sync with stored token S->>CRM: Sync emails & calendar events CRM->>CRM: Auto-log activities on linked records
Integration Setup Steps
  1. Navigate to CRM > Integrations
  2. Click "Connect Google" or "Connect Outlook"
  3. Complete the OAuth consent screen in the popup window
  4. Configure sync preferences (direction, folders, frequency)
  5. Verify connection status shows "Connected" on the Integrations page

Email Thread Viewer

The CrmEmailThread component displays synced email conversations directly inside the CRM record detail view. It supports:

  • Linked Records — each thread is associated with one or more CRM contacts, leads, or accounts
  • Thread View — emails are grouped by conversation subject, displayed in chronological order with newest at top
  • Reply & Forward — users can reply to or forward synced emails directly from the CRM interface; replies are sent via the connected email provider
Auto-Activity Logging

When Auto-log Activities is enabled, every synced email matching a CRM-linked contact automatically creates a Call/Email activity record on the corresponding Lead, Contact, or Account. The activity includes sender, recipients, subject, timestamp, and a snippet of the body. No manual entry required.

Privacy Boundary

Only emails from/to CRM-linked contacts are synced and auto-logged. Emails between personal contacts or unrelated parties are never captured by the CRM. This ensures PDPA compliance and protects employee personal communications.

Warning: Disconnecting OAuth revokes all sync. Existing auto-logged activities remain but no new emails will be captured. To reconnect, you must complete the OAuth consent flow again.

Custom Fields

Custom Fields allow CRM Admin to extend the data model without code changes. Add organisation-specific data points — such as product interests, referral sources, or compliance flags — to any CRM record type. This two-tier approach keeps the core schema clean while supporting unlimited business-specific extensions.
Two-Tier Approach
Tier 1 — Admin: Create Field Definitions

CRM Admin defines the field schema: label, type, required status, visibility, and which record types the field applies to. Fields are created once and applied across the organisation.

Tier 2 — Users: Fill Field Values

CRM users fill in the custom field values on individual records. Values are editable inline from the record detail view and filterable in list views.

Admin: Setup Steps
  1. Navigate to CRM > Settings > Custom Fields
  2. Click "Add Field"
  3. Enter the Field Label and select a Field Type
  4. Configure the field settings (see table below)
  5. Select which record types the field applies to (Lead, Account, Contact, Opportunity, Activity)
  6. Click "Save" — the field is immediately available on applicable record types

User Perspective

Once a custom field is created by Admin, it appears on the record detail form for all applicable record types. Users can:

  • View custom field values in the record detail section
  • Edit values inline by clicking the field — changes save immediately
  • Filter list views by filterable custom fields (e.g., show all leads where "Product Interest = Trust")
Good: Admin creates a "Product Interest" dropdown field on Lead, with options: Trust, Will, Wealth Management, Corporate Services. Sales Rep selects from the dropdown when qualifying the lead.
Bad: Sales Rep asks IT to add a column to the database for tracking product interest. Wrong approach. Use Custom Fields — no code changes or database migrations needed.
Enforcement: The system validates required custom fields on save. If a required custom field is empty, the save is blocked with a clear validation message identifying the missing field. This operates identically to core mandatory field enforcement.

Workflow Automation

Automate repetitive CRM tasks with trigger-action rules. Workflows listen for specific trigger events, evaluate optional conditions, and execute one or more actions automatically. Eliminate manual follow-ups, ensure consistent processes, and reduce human error.

Workflow Builder UI

The Workflow Builder is a visual rule builder accessible from CRM > Settings > Workflows. It consists of three panels:

Trigger Picker

Select the event type, record type, and specific field/stage that starts the workflow. Example: "When Opportunity stage changes to Negotiation"

Condition Builder

Add optional filters that must be true for the workflow to execute. Example: "AND Estimated Value > MYR 100,000" — if conditions don't match, the workflow is skipped

Action Configurator

Define one or more actions to execute when the trigger fires and conditions match. Actions execute in order. Example: "1. Send email, 2. Create follow-up activity"

Workflow Lifecycle
StateDescriptionTransition
DraftWorkflow is being configured, not yet active. Can be edited freely.Created by default → toggle Active
ActiveWorkflow is live and will execute when triggered.From Draft → toggle on
InactiveWorkflow is paused; triggers are ignored. All configuration is preserved.From Active → toggle off

Each workflow maintains an execution history log showing every run: trigger time, conditions evaluated (match/no-match), actions executed, and any errors encountered. This log is accessible from the workflow detail view.

Import & Export

The Import & Export module enables bulk data management for onboarding historical data, periodic migrations from external systems, and compliance-related data exports. All operations are audited.
Import Flow
flowchart LR A[Upload CSV] --> B[System Analyzes Headers] B --> C[Map CSV Columns to CRM Fields] C --> D[Validate Data] D --> E[Execute Import] E --> F[Show Results] F --> G[Created / Updated / Errors]
Import Steps (Detailed)
  1. Navigate to CRM > Import/Export
  2. Download the Template for the target entity (Lead / Account / Contact / Opportunity)
  3. Fill data in the template — preserve the header row exactly as provided
  4. Upload the completed CSV file
  5. Review field mapping — the system auto-maps columns by header name; adjust any unmapped columns manually
  6. Click "Validate" to check data without importing — this runs all validation rules and shows errors
  7. Click "Execute Import" to process the data
  8. Review the results summary: Created / Updated / Skipped / Errors
Export Steps

1. Apply the desired list filters on the entity list view (e.g., Leads — filter by Source and Date Range)
2. Click "Export" in the list toolbar
3. Select which fields to include in the export
4. Click "Download" — a CSV file is generated and downloaded

Import Rules
RuleEnforcementDetail
Template Headers Must MatchSystemCSV column headers must match the template exactly. Unrecognized headers cause the column to be skipped with a warning.
Duplicate Check on ImportSystemExisting records are matched by IC/Company No. + Name. Duplicates are updated (not duplicated) using the "upsert" pattern.
Required Fields EnforcedSystemRows missing required fields are flagged as errors and skipped. They do not block the rest of the import.
Max 10,000 Rows per ImportPolicyLarger datasets must be split into multiple imports. Contact CRM Admin for bulk imports exceeding this limit.
Error Rows SkippedSystemRows with validation errors are skipped — the import does not roll back. Valid rows are committed; error rows are listed in the results.
Important: All imports and exports are logged in the audit trail with user, timestamp, row counts, and file name. Import logs are retained for 7 years in compliance with BNM record-keeping requirements.
