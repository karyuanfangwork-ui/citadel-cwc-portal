Territory Management

Territories define geographic or industry segments for lead routing and pipeline accountability. Each territory has assigned members, routing rules, and an optional hierarchy for rollup reporting.
Territory Lead Routing Flow
flowchart TD A[New Lead Created] --> B[Territory Routing Rules] B --> B1[Industry + Location] B1 --> C[Matched Territory] C --> D[Auto-assign to Territory Member] D --> D1[Round-robin or Capacity-weighted] D1 --> E[Rep Notified]
Territory Structure
Territory Entity Fields

Each territory record contains the following key fields:

  • Name — descriptive label (e.g., "Sabah Geographic")
  • Type — Geographic / Industry / Hybrid
  • Parent Territory — optional nesting for hierarchy rollup
  • Members — users assigned to this territory
  • Routing Rules — conditions that match incoming leads to this territory
Territory CRUD Workflow
  1. Admin creates territory — defines name, type, and optional parent
  2. Assigns members — adds users with Owner, Member, or Read-Only roles
  3. Configures routing rules — sets conditions based on industry, location, lead source, or deal value
  4. Territory appears in CRM nav — for all assigned members, the territory is visible and actionable
Territory Member Roles
RoleAccessDescription
OwnerFull read/write on territory records, manage membersCan add/remove territory members, modify routing rules, and owns pipeline accountability for the territory
MemberRead/write on assigned recordsCan create, edit, and progress leads/opportunities assigned within the territory
Read-OnlyView onlyCan view territory records and pipeline but cannot create or edit; typically used for cross-territory visibility or executive oversight
Routing Rules
Routing Rule Conditions

Routing rules determine which territory a new lead is assigned to. Conditions are evaluated based on:

  • Account Industry — e.g., Timber, Finance, Construction
  • Account State/Region — e.g., Sabah, Sarawak, Selangor
  • Lead Source — e.g., Referral, Website, Event
  • Deal Value Threshold — e.g., >MYR 500,000 routes to Enterprise territory
Territory Hierarchy
Nesting Support

Territories support optional parent-child nesting for hierarchical rollup reporting. Example hierarchy:

Malaysia
    └─ Klang Valley
        └─ KL City
Good: Lead from Sabah with timber industry → matches Sabah Geographic + Timber Industry territories → assigned to Sabah rep specializing in timber.
Bad: All leads assigned to one senior rep regardless of location → Rep overwhelmed, other territories under-served.

Quota Management

Quotas define sales revenue targets per rep and territory, tracked against actual closed-won revenue. Quotas are set quarterly by Management and entered by CRM Admin.
Quota Dashboard
/crm/quotas

The Quota Dashboard at /crm/quotas displays:

  • Current quarter targets per rep and territory
  • Attainment percentage with colour-coded indicators
  • Trend charts showing quota progress over the quarter
Quota CRUD Fields
FieldDescriptionExample
PeriodQuarterly target periodQ1 2026, Q2 2026, Q3 2026, Q4 2026
Target AmountRevenue target in MYRMYR 2,500,000
Assigned ToUser or territory receiving the quotaAhmad Razali / Klang Valley Territory
Quota TypeWhat is being measuredRevenue / Deal Count / New Accounts
Quota Attainment Calculation
Formula

Attainment % = (Closed Won Value in Period ÷ Quota Target Amount) × 100

Example: Closed Won = MYR 2,250,000 / Target = MYR 2,500,000 → Attainment = 90%

Attainment Tracking
Real-Time Updates

Attainment is calculated in real-time from Closed Won opportunities. The percentage auto-updates every time a deal is closed — no manual refresh or recalculation required.

Manager View
Team-Level Insights

Managers have access to:

  • Team-level quota rollup — aggregate attainment across all team members
  • Individual rep attainment — side-by-side comparison of each rep's progress
  • Territory-level aggregation — combined attainment for all reps in a territory
Attainment Colour Coding
≥90% — On Track
70–89% — At Risk
<70% — Behind
Important: Quota targets are set by Management quarterly. CRM Admin enters the targets. Reps cannot modify their own quotas.

Mobile Interface

The CRM provides a fully responsive mobile interface for field reps who need access away from their desk. The interface automatically adapts to the device screen size, providing an optimised experience at every breakpoint.
Mobile Components
CrmMobileNav

Bottom navigation bar with core module icons. Replaces the sidebar on mobile devices for thumb-friendly access.

CrmMobilePipeline

Swipeable kanban cards for opportunity stage management. Swipe left/right to advance or regress pipeline stages.

CrmMobileList

Touch-optimised list views with pull-to-refresh. Tappable rows with large hit areas for easy navigation.

CrmMobileForm

Large tap targets and simplified layout for data entry on mobile. Fields are stacked vertically with ample spacing for fat-finger-friendly input.

CrmResponsiveLayout

Auto-switches layout between desktop, tablet, and mobile at defined breakpoints. Ensures optimal UI for every device size.

Responsive Breakpoints
BreakpointLayoutNav StyleAvailable Features

Tablet (768–1023px)Collapsed sidebar + overlayHamburger menu + slide-out sidebarAll features
Mobile (<768px)Bottom nav barBottom icon navigationCore features (Dashboard, Leads, Pipeline, Activities, Contacts)
Mobile Bottom Nav Items
Bottom Navigation Tabs

The mobile bottom navigation provides quick access to:

  • Dashboard — personal KPIs and team overview
  • Leads — lead list, creation, and management
  • Pipeline — swipeable opportunity kanban
  • Activities — today's tasks and upcoming activities
  • More — Accounts, Contacts, Reports (overflow menu)
Mobile Best Practices
  1. Log activities immediately after customer meetings using the mobile form — don't wait until you return to the office
  2. Use pipeline kanban swipe to quickly update opportunity stages on the go — much faster than desktop for simple stage changes
  3. Pull-to-refresh on list views to get the latest data — ensures you're always working with current information
  4. Use "Call" button on Contact detail to dial directly from CRM — tap the phone icon to initiate a call without switching apps
  5. Avoid bulk operations on mobile — use desktop for import/export and mass updates; mobile is optimised for single-record actions
Good: Field rep visits client, uses mobile CRM to log meeting activity and update opportunity stage on the spot.
Bad: Field rep waits until end of day to log 5 customer meetings from memory → data quality suffers and SLA clock already expired.

Personal Tools

Activity Reminders
POST /activities/:id/remind

Sends an email reminder to the assigned user for a specific activity.

Reminder Types
TypeTriggerDetail
Auto-ReminderSystem-generatedSystem automatically sends a reminder 1 hour before the scheduled activity due time
Manual ReminderUser or Manager actionUser or manager can trigger the "Remind" action on any activity at any time
Tracking Field

The reminderSent boolean field on the Activity model tracks whether a reminder has been dispatched. Once set to true, auto-reminders will not re-fire for the same activity.

Activity Edit & Delete
PATCH /activities/:id

Update any activity field: type, subject, notes, due date, status. Changes are logged in the audit trail.

DELETE /activities/:id

Soft-delete — activity is marked deleted and retained in audit trail per BNM retention requirements. Not permanently removed.

Restrictions
RestrictionEnforcementDetail
Cannot delete complaint activitiesSystemThe system blocks deletion of any activity with type complaint. This is a hard system enforcement — no bypass.
Managers can edit any team member's activityPolicyManagers have edit access to all activities within their team scope for oversight and correction.
Reps can only edit own activitiesSystemSales reps are restricted to editing activities they created or are assigned to. Cannot modify other reps' activities.
Warning: Deleted activities are not removed from the database. They are soft-deleted and retained for 7 years per BNM audit requirements. Deleting a complaint activity is blocked by the system.
