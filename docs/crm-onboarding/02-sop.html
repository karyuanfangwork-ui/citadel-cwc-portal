SOP ID: SOP-CRM-001
Version: 1.0
Owner: Sales Representative
Approver: Sales Manager
Frequency: Per event
Last Reviewed: May 2026
Objective: Ensure every prospect is captured accurately in CRM on the same business day first contact is made, with all mandatory fields populated, deduplication performed, and an initial activity logged within 24 hours.
Scope

Applies to all sales representatives capturing any new prospect (individual or corporate) regardless of lead source — referral, cold call, website, event, or walk-in.

Preconditions
  • User holds crm:write permission
  • Prospect information obtained from an approved source
  • User has confirmed no existing record via search
Responsible Roles
Sales Representative — Creator Sales Manager — Reviewer CRM Admin — Auditor
Process Steps
#StepDecision / Validation
1Open global search — enter prospect name, IC, or company registrationIf match found → review existing record. Do not create duplicate.
2Navigate to Leads → + New Lead—
3Fill all required fields: Name, Source, Phone/Email, Assigned ToAll four fields mandatory — form will not save otherwise
4Review duplicate warning if displayedIf system flags similarity ≥ 85% → investigate before saving
5Click Save LeadSystem timestamps creation, records creator identity
6Add initial activity note (Call / Meeting / Email) within 24 hoursActivity date must match actual date of first contact
Validation Rules
FieldRuleError if Violated
Lead NameMinimum 5 characters; full legal name requiredForm save blocked
SourceMust be selected from dropdown; cannot be blankForm save blocked
ContactPhone or Email — at least one requiredForm save blocked
DuplicateSystem checks name similarity ≥ 85% and exact IC/phone matchWarning shown — user must acknowledge
SLA Requirements
MetricTargetEscalation if Missed
Lead creationSame business day as first contactManager notified after 24h
First activity loggedWithin 24 hours of lead creationManager alert + flagged in report
Lead assignmentWithin 4 business hoursAuto-alert to manager at 4h
Exception Handling
  • If prospect refuses to provide contact info: create lead with note explaining situation; escalate to manager
  • If source is unclear: select "Other" and add clarifying note
  • If duplicate confirmed: merge records — only CRM Admin can execute merge
Audit Requirements
  • All lead creations are timestamped and attributed to the creating user
  • Field changes are recorded in the audit log with before/after values
  • Duplicate acknowledgements are logged
  • Audit records retained minimum 7 years per BNM data retention guidelines
KPI Impact
Lead Response Time Lead Conversion Rate Data Completeness % Duplicate Rate
Operational Risk: Delayed lead creation or missing Source field directly degrades pipeline reporting accuracy and marketing attribution data.

SOP ID: SOP-CRM-002
Version: 1.0
Owner: Sales Manager
Approver: Senior Manager
Frequency: Daily review
Risk Level: High
Objective: Ensure all new leads are assigned to an active, appropriate sales representative within 4 business hours of creation. Unassigned leads receive no outreach and represent direct revenue leakage.
Preconditions
  • Manager holds crm:admin permission
  • Lead exists in Unassigned or New status
  • Target rep is active (not on leave, not suspended)
Process Steps
#Step
1Open Leads list — filter by Status = Unassigned at start of each business day and at midday
2Review lead details: source, estimated value, industry, geographic territory
3Check Team Dashboard for rep workload and capacity
4Click the lead → Assign → select best-fit representative
5System sends automatic notification to the assigned rep
6Confirm assignment is visible in Team Dashboard → Lead Assignments
7If reassigning an existing lead: add a Reason for Reassignment note (required)
SLA & Escalation
TriggerSLAEscalation
Lead created — unassigned4 business hoursAuto-alert to manager at 4h
Still unassigned at 8hBreachAuto-alert to Senior Manager
Reassignment requestSame business dayManager notification
Validation Rules
  • Cannot assign to suspended, inactive, or off-system users
  • Cannot assign to self (Manager self-assignment requires Senior Manager approval)
  • Reassignment requires a written reason note — system enforces this
  • Assignment must be completed before first activity is logged
Exception Handling
  • If all reps at capacity: escalate to Senior Manager for temporary pool assignment
  • If lead requires specialist knowledge: assign to senior rep and note the reason
  • If rep is on unplanned leave: reassign immediately; do not leave unactioned
KPI Impact & Audit
Lead Response Time Lead Assignment Rate SLA Compliance Rate
Risk: Every hour a lead is unassigned is an hour of zero outreach. High-value leads that sit unassigned for > 8 hours have statistically lower conversion rates.

SOP ID: SOP-CRM-005
Version: 1.0
Owner: Sales Representative / Sales Manager
Risk Level: High
Objective: Ensure all discount grants, deal exceptions, and high-value transactions follow the defined approval authority matrix before any commitment is made to the customer.
Approval Triggers (What Requires Approval)
SituationApprover Required
Discount 1%–5%Sales Manager
Discount 6%–15%Senior Manager
Discount >15%Senior Manager + Finance Director
Deal value > MYR 500,000Director
New account with credit facilityCompliance + Manager
Term extension / deal exceptionSales Manager
Submitter Process (Sales Rep)
#Step
1Open the relevant opportunity or account record
2Click Request Approval in the action bar
3Select the correct approval type from the dropdown
4Attach all supporting documents (proposal, pricing sheet, KYC)
5Write a specific justification note — vague notes will be rejected
6Click Submit — approver is notified immediately
7Monitor Approvals tab — follow up if no response in 24h
Approver Process (Manager)
#Step
1Open Notifications → click pending approval request
2Review the request: justification note, attached documents, deal context
3Verify supporting documents are complete before deciding
4Select Approve or Reject — a decision comment is mandatory
5System notifies submitter of the decision immediately
6For rejected requests: submitter may revise and resubmit once corrected
SLA & Escalation
Approval TypeResponse SLAEscalation
Standard approval1 business dayAuto-escalate to Senior Manager at 24h
Urgent (customer deadline)4 business hoursPhone call to approver required at 3h
Director-level approval2 business daysManager to follow up directly
Validation & Audit Rules
  • Cannot submit without at least one attached document and a justification note
  • Self-approval is prohibited — system blocks if submitter = approver
  • All approval decisions (including rejections) are permanently logged with timestamp and approver identity
  • Approval records are retained 7 years minimum

SOP ID: SOP-CRM-006
Version: 1.0
Owner: Customer Service Team
Approver: Customer Service Manager
Risk Level: High
Regulatory: BNM Guidelines — 7-year retention
Objective: Ensure all customer complaints are acknowledged within 2 hours, investigated thoroughly using CRM history, and resolved within the SLA window. All complaints are BNM-audit-ready.
Process Steps
#StepOwner
1Receive complaint (phone / email / walk-in / via sales rep)CS Rep
2Open customer Contact record in CRM (search by name or IC)CS Rep
3Log activity: Type = Complaint; Subject = brief description; Note = full complaint detailsCS Rep
4Assess severity: High (financial loss, BNM reportable, media risk) or StandardCS Rep
5If High severity: escalate to CS Manager immediately by phone; do not wait for email responseCS Rep
6Acknowledge to customer: confirm complaint received, provide reference number and expected resolution timelineCS Rep / Manager
7Investigate using account and activity history in CRM; involve relevant sales repCS Rep / Manager
8Communicate resolution to customer within SLACS Manager
9Log resolution note on the complaint activity; mark as ResolvedCS Rep
10Archive complaint record — do not deleteCRM Admin
SLA & Escalation Matrix
SeverityAcknowledgeResolveEscalation if Breached
High30 minutes4 business hoursSenior Manager + Compliance + CEO notification
Standard2 hours2 business daysSenior Manager notification at breach
Escalation Path
1 CS Representative — first responder
2 CS Manager — High severity or unresolved > 2 days
3 Senior Manager + Compliance — BNM-reportable or reputational risk
4 CEO — critical escalation requiring executive response
Audit & Regulatory Requirements
  • All complaints logged with full details — activity record cannot be deleted
  • Retained minimum 7 years per BNM Financial Consumer Protection Framework
  • Monthly complaint summary report submitted to CS Manager and Compliance
  • Recurring complaints on same issue trigger root-cause analysis within 30 days

SOP ID: SOP-CRM-007
Version: 1.0
Owner: CRM Admin
Frequency: Weekly (every Monday)
Risk Level: Medium
Objective: Maintain data accuracy, completeness, and consistency across all CRM records on a weekly basis to support reliable reporting, accurate pipeline forecasting, and BNM compliance.
Weekly Audit Process Steps
#StepTool / Report
1Navigate to Reports → Data Quality ReportCRM Reports module
2Run duplicate detection — review all records flagged ≥ 85% similarityDuplicate Detection Report
3Investigate each duplicate pair: verify which is the master recordRecord comparison view
4Execute merge for confirmed duplicates (Admin-only action)Merge function in record detail
5Identify leads with blank Source field — contact owning rep to updateLeads list filter: Source = blank
6Review stale opportunities (> 30 days no update) — notify assigned repOpportunities filter: Last Updated > 30 days
7Check KYC document completeness for all active accountsKYC Compliance Report
8Export and archive the weekly data quality scoreReports → Export CSV
9Email data quality summary to Sales Manager and ManagementEmail / CRM notification
Data Quality Standards
MetricAcceptable ThresholdAction if Breached
Data Completeness> 95% of mandatory fields filledNotify rep + manager; escalate after 3 weeks
Duplicate Rate< 2% of total recordsImmediate review + merge; root cause investigation
KYC Completeness100% of active accountsCompliance alert; account flagged; rep notified
Stale Opportunities< 10% of pipeline > 14 days oldManager coaching; rep follow-up required
Exception Handling
  • If rep is unavailable to fix their records: CRM Admin may update with note "Updated by Admin on [date]"
  • Disputed duplicates (unsure if same person): create a "Potential Duplicate" tag; do not merge until confirmed
  • Records that cannot be completed (prospect refused to provide info): add "Incomplete — Reason: [X]" note and flag for manager review

Data Completeness % Duplicate Rate KYC Compliance Rate
