# D1 host capacity probe (local artifact; not deployed)

Run from the **Linux Docker host** using `python3 scripts/disk-capacity.py --inventory --backup-dir /path/to/backups`. No production command or cleanup is authorized by this file. The probe reads root filesystem blocks/inodes, `/proc/meminfo`, Docker disk usage/images/build cache and volume names, container JSON-log byte sizes, readable volume mountpoint sizes (including PostgreSQL and uploads), and backup file sizes/ages. Unreadable volume/log sizes are `null`, not zero; Docker disk usage is not an additive breakdown of root usage. It does not enter containers, delete artifacts, inspect container environment, or read remote S3 backups. Use `df` plus approved host-wide inventory to reconcile other filesystem consumers; retain dated JSON outputs outside this repository for growth trends. A single sample cannot establish a trend or explain production's 42 GB used.

Example thresholds are **provisional proposals**, not approved production policy: available root space below either 8 GiB or 15%, inode free below 10%, available RAM below 512 MiB, swap usage over 80%. Exit 0 = OK, 2 = breached, 3 = unknown/probe failure (including non-Linux memory or unavailable inode count). The JSON output contains the measured values and reasons. Do not interpret swap use as OOM; inspect process/container state separately. The probe emits no notification. Operations must nominate an owner, approve thresholds, schedule execution and configure an external alert transport to notify on both exit 2 and 3, with acknowledgement/escalation and a live end-to-end delivery test before calling D1 alerting complete. Test thresholds locally with `python3 -m unittest discover -s scripts -p 'test_disk_capacity.py'`; synthetic tests do **not** verify on-call delivery.

D2 remains separately gated: reviewed disposable-artifact allowlist, verified backup/restore and approval before any production cleanup, then free-space, Docker state and application-health readback. Never prune volumes, active images or unverified backups as an automatic alert response.
